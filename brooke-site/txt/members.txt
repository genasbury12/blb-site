<!--
  ============================================================
  PURPOSEFUL PENNIES  ·  MEMBER HOME   /members
  Showit + MemberSpace
  ============================================================

  WHAT THIS PAGE IS
  The logged in home screen. The first thing a member sees after login
  and the page she will come back to most. One screen, calm, and it
  answers three questions without scrolling: what is new, what is next,
  and where do I go.

  ------------------------------------------------------------
  MEMBERSPACE SETUP
  ------------------------------------------------------------
  1. INSTALL CODE. Paste the MemberSpace install snippet into Showit
     under Settings > Advanced > Head HTML so it loads on every page.
     Grab it from MemberSpace: Customize > Integrations > Showit.

  2. PROTECT THESE PATHS. In MemberSpace, create the plan, then protect
     by URL path. Showit uses flat page slugs, so there is no nesting
     to inherit from. Every member page is a top level slug beginning
     members- and protection has to be a prefix rule:

        /members            <- this page
        /members-*          <- every other member page

     VERIFY THE WILDCARD ACTUALLY MATCHES before launch. Add a member
     page, log out, and try to open it. A prefix rule that silently
     fails to match does not throw an error, it just serves paid
     content to the public. Test it, do not assume it.

     Leave the whole public site unprotected. Never protect
     /membership or /membership-thank-you.

     NOTE ON FILES. PDFs live under /members-files/ which is an asset
     path, not a Showit page. MemberSpace URL protection does not
     cover direct file links, so anyone given a URL can open one.
     If that matters, host the PDFs as MemberSpace Space file content
     instead, which gates them properly and reports who opened what.

  3. MEMBERSPACE LINK. Grab it from Customize > Integrations > Showit >
     MemberSpace Link. It is one link that adapts by itself: it shows
     login to a visitor and account to a member.

     It only needs pasting in FOUR places in the whole build, because
     every "My account" link now routes to /members-account instead:

        this page   1  the logged out notice at the top
        /members-account  3  the two settings buttons and the
                             renewal date link

     Anything marked class="ms-link" with href="#" still needs it.
     Nothing else does.

  4. DATA ATTRIBUTES USED HERE. These are real MemberSpace attributes,
     confirmed against their developer docs:

        data-ms-member-info="firstName"   prints the member's first name
        data-ms-hide="auth"               hidden once she is logged in
        data-ms-show="plan(PLAN_ID)"      founding member badge only

     On any data-ms-show element MemberSpace recommends inline
     style="display:none" so it does not flash before the script runs.
     That is done below. Swap PLAN_ID for the real founding plan id,
     which sits at the end of that plan's signup link.

  5. MEMBER MENU. MemberSpace shows its own floating member button with
     a What is New feed. Keep it on. This page is the warm front door,
     that button is the quick shortcut. They do not fight.

  ------------------------------------------------------------
  TWO THINGS MEMBERSPACE DOES NOT DO
  ------------------------------------------------------------
  The sales page promises a community and a monthly live session.
  MemberSpace gates pages and takes payments, and it gives comments and
  reactions on content, but it is not a community platform and it does
  not host live video. So both need a home before doors open:

     The Circle    ->  a private Facebook group is the pragmatic
                       choice, or a Circle account later. Point
                       COMMUNITY_URL at whichever wins.
     Live sessions ->  Zoom or Google Meet. The join link lives on a
                       protected page, and the replay is embedded on
                       /members-sessions afterwards.

  Nothing on this page breaks either way. Both are single constants in
  the config block at the bottom.

  FORMATTING RULE. Zero em dashes, zero en dashes. The separator is the
  diamond glyph.
  ============================================================
